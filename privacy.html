Summary

  • Emails are sent only for account purposes: a link to confirm your email address and, on request, a link to reset your password. There are no newsletters or marketing emails.

What data is processed

Visiting the website

When you open the site, your browser connects to the web server for the pages and to the game server (API). The web server (nginx) and the game server write technical logs:

  • Web server access logs (pages and game server): your IP address, time, request method, requested path (without query string), protocol, response status, response size and your browser's user agent; for the game server also the processing time. The referrer (the page you came from) and the query string are not logged.
  • Game server log: one line per request with method, path (without query string), response status, duration, your IP address, time and a request id. Request headers, bodies, passwords and tokens are not logged. If an email cannot be delivered, only the domain part of the recipient address (for example example.com) is logged.
  • To block password guessing, the game server counts sign-in and similar requests per IP address. These counters are kept only in the server's memory for up to about one hour (a lockout lasts 30 minutes) and are not written to disk.

Your account

When you create an account, the following is stored:

  • username, email address and display name,
  • Discord handle and Telegram handle (both optional),
  • your password as a one-way hash (the password itself is never stored),
  • creation and last-change timestamps, the time your email address was confirmed, and account status flags (active, administrator).

The email address is used to send the account emails described below and to let you request a password reset with it. The Discord and Telegram handles [STATE WHAT THE DISCORD AND TELEGRAM HANDLES ARE USED FOR, e.g. "to contact you about prizes"].

Account emails

If email is enabled on this server, the game sends plain-text emails in two cases only:

  • Email confirmation after registration (and when you ask for a new link): a link that confirms your address. It is valid for 48 hours.
  • Password reset when you ask for it with your username or email address: a link to choose a new password. It is valid for 30 minutes. Resetting the password signs out all your sessions and also confirms your email address.

Each email contains your email address, your display name (or username) and the one-time link. Every link works only once. The server stores only a hash of the link's token together with its purpose, creation time, expiry time and the time it was used; earlier unused links of the same kind are invalidated when a new one is sent, and at most one email per kind is sent per minute. The game server keeps no copy of the emails. The emails are delivered through the email provider named under Recipients.

Sign-in sessions

Each sign-in creates a session that is valid for 24 hours. For each session the server stores a hash of the random session token, creation and expiry time, your IP address and your browser's user agent. Changing or resetting your password ends all your sessions.

Security log

Registration, sign-in, sign-out, password changes, password reset requests and resets, email confirmations and account deletion are recorded in a security log with the event type, success or failure (and a short reason such as "invalid credentials"), time, IP address and user agent. Failed attempts that cannot be matched to an account are logged without an account reference.

Administrator actions

Every change made by an administrator (for example creating or deleting rounds, changing settings, muting players or granting the administrator role), every look at the account list and every administrator request refused because the signed-in account is not an administrator is recorded in the same security log: the administrator's account (or the kind of access used), the request method and path, success or failure, time, IP address and user agent. Request contents are not recorded.

Gameplay and results

  • When you join a round, a player entry is created with your player name (your display name), a link to your account, the time you joined, a hash of your per-round player token and your game state (balances, upgrades, trades, scores).
  • When a round ends, the final standings (player name, rank, score, scoring mode, round type, number of participants and finish time) are copied into a results archive. You see them under My results.
  • Rounds can include computer-controlled opponents. They are always shown as "Bot" with a BOT badge in rankings and results; they are not people and no personal data is processed for them.

Chat

If chat is enabled for a round, your messages are delivered to the players currently connected to the same round, together with your player name and the time. Chat messages are held in memory only for delivery; they are not written to the database or to the logs and there is no chat history.

Administrators can moderate the chat. They can mute a player in a round for 1 minute up to 24 hours or until the round ends; for each mute the server stores the round, the player entry, the end of the mute, when it was set and by which administrator. A muted player's messages are rejected. Administrators can also clear a round's chat, which removes the messages from the screens of all connected players; nothing is stored for this.

Backups

The game database is backed up nightly. Backups contain all data described above and are kept for 14 days on the server [ADD OFF-SERVER BACKUP LOCATION AND RETENTION, IF ANY]. Data you deleted can therefore remain in backups until they expire.

Browser storage and cookies

The game uses your browser's local storage (keys beginning with mining-tycoon:) only for things it needs to work:

  • your sign-in token, username, display name and player name,
  • the game server address,
  • the round and player you are in, and a per-round player token so you can rejoin,
  • a snapshot of your last finished round (shown under Last Game Highscores),
  • one interface preference (whether the debug panel is open) and a cache of game settings (cache entries expire after 7 days).

Administrators who sign in to the administration page also have their administrator session kept in the browser's session storage, which is removed when the tab is closed or on sign-out.

On sign-in the game server also sets one cookie, app-auth-session (HttpOnly, SameSite=Strict, sent only over HTTPS in production mode, valid for 24 hours), which holds your session token. It is technically necessary and is removed when you sign out.

No analytics, advertising or tracking cookies or similar technologies are used, so no consent banner is shown. Signing out, changing your password, deleting your account or an expired sign-in removes the sign-in entries and all per-round player tokens from this browser. The other entries stay until you remove them through your browser settings, which you can do at any time.

Security

  • Passwords are stored only as Argon2id hashes. Session tokens, per-round player tokens and the tokens of one-time email links are stored only as SHA-256 hashes, so a copy of the database does not contain usable sign-ins or links.
  • Connections are encrypted with HTTPS (TLS); plain HTTP is redirected to HTTPS [CONFIRM THAT HTTPS IS ENABLED].
  • The pages use a strict Content Security Policy: scripts, styles and fonts load only from this site, and the browser may connect only to this site and the game server.
  • Sign-in and email requests are rate-limited, and repeated failed sign-ins from one IP address cause a temporary lockout.
